# 集合通信调试过程

目标：Gloo 进程组 + torch_npu 对称内存做窗，pypto 通信算子做 TSTORE → TPUT → allreduce。不走 `orch.allocate_domain` / HCCP。

## 决策（2026-08-13 问答）

- 数据面顺序：先 TSTORE，再 TPUT，再 `pld.tensor.allreduce`。
- 窗：`pld.import_window_buffer` 声明槽位，运行时由 `RunConfig.domain_provider` 注入 SHMEM 地址。
- 同步：优先试 `notify`/`wait`，失败只记日志；主路径用 Gloo barrier。
- 入口：`examples/distributed/08_gloo_shmem_collectives.py`。
- dtype/shape：FP16，`[1024]`（`pld.tensor.allreduce` 不支持 BF16）。
- 拉起：`torchrun --nproc_per_node=2`，backend=`gloo`。
- 改动默认只落在 **pypto 仓**。例外：只有 TPUT 打不到 SHMEM GM、或 Worker fork 弄坏 SHMEM 时才回头动 torch_npu / shmem / simpler 子模块。

## 实跑记录

环境：`source env.sh` + `shmem/install/set_env.sh`，`torchrun --nproc_per_node=2`，backend=`gloo`。

1. **先 SHMEM 再 `Worker.init`**：chip child `wait status 11`（SIGSEGV）。父进程 torch_npu 占过设备后再 fork 不稳。  
   处理：先 `compile` + `prepare()` fork，再 `empty`/`rendezvous`。

2. **buffer 名**：codegen 把 LHS 编成 `data_buf__ssa_v0`。provider 去掉 `__ssa_v*` 再查布局。

3. **`child_memory` 校验**：`submit_next_level` 要求指针在 Worker `_child_alloc_prov` 里。  
   处理：`make_shmem_domain_provider(..., simpler_worker=worker._w)` 登记 window base / slice / CommContext。

4. **TSTORE 已 launch**：`chip_process ready` 后进入 kernel。rank1 报  
   `MTE accesses an invalid GM address or the cross-device memory access times out`（`0x800000`），`sched_error_code=100`。  
   结论：SHMEM 的 `rendezvous().buffer_ptrs` 作为 `CommContext.windowsIn[peer]` 时，pto-isa TSTORE 的 MTE 跨 die 访问失败。这是计划里写的「TPUT/TSTORE 打不到 SHMEM GM」例外，**没有**改用 HCCL AllReduce。

5. 日志副本：goal scratch `gloo_tput_run1.log`（同一次失败也作为 run2 的环境复现记录）。

单元测试：`pytest tests/st/distributed/test_gloo_shmem_window.py` 6 passed（打包 CommContext、切窗、live-input golden、`import_window_buffer` 导出）。

## 已知风险

- NPUSHMEM 无 `barrier`/`put_signal`，跨卡可见性靠 Gloo CPU barrier + `npu.synchronize`。
- L3 Worker 会 fork chip 子进程；SHMEM 在 torchrun 父进程里 init。若子进程用不了父进程的 SHMEM VA，需要再改 simpler 或改成进程内 launch。
- `pld.tensor.allreduce` 是 host builtin，每进程只 launch 本地一张卡上的 chip kernel；两边进程各跑一次，靠注入的 `CommContext.rankNum=2` 配对。
