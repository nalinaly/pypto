# 集合通信调试过程

目标：Gloo 进程组 + torch_npu 对称内存做窗，pypto 通信算子做 TSTORE → TPUT → allreduce。不走 `orch.allocate_domain` / HCCP。

## 决策（2026-08-13 问答）

- 数据面顺序：先 TSTORE，再 TPUT，再 `pld.tensor.allreduce`。
- 窗：`pld.import_window_buffer` 声明槽位，运行时由 `RunConfig.domain_provider` 注入 SHMEM 地址。
- 同步：优先试 `notify`/`wait`，失败只记日志；主路径用 Gloo barrier。
- 入口：`examples/distributed/08_gloo_shmem_collectives.py`。
- dtype/shape：FP16，`[1024]`（`pld.tensor.allreduce` 不支持 BF16）。
- 拉起：`torchrun --nproc_per_node=2`，backend=`gloo`。
- 改动默认只落在 **pypto 仓**。例外：只有 TPUT 打不到 SHMEM GM、或 Worker fork 弄坏 SHMEM 时才回头动 torch_npu / shmem / simpler 子模块。

## 实跑记录

环境：`source env.sh` + `shmem/install/set_env.sh`，`torchrun --nproc_per_node=2`，backend=`gloo`。

1. **先 SHMEM 再 `Worker.init`**：chip child `wait status 11`（SIGSEGV）。父进程 torch_npu 占过设备后再 fork 不稳。  
   处理：先 `compile` + `prepare()` fork，再 `empty`/`rendezvous`。

2. **buffer 名**：codegen 把 LHS 编成 `data_buf__ssa_v0`。provider 去掉 `__ssa_v*` 再查布局。

3. **`child_memory` 校验**：`submit_next_level` 要求指针在 Worker `_child_alloc_prov` 里。  
   处理：`make_shmem_domain_provider(..., simpler_worker=worker._w)` 登记 window base / slice / CommContext。

4. **TSTORE 在 L3 fork 子进程里 MTE `0x800000`**：`chip_process ready` 后 rank1 报  
   `MTE accesses an invalid GM address or the cross-device memory access times out`。  
   诊断（父进程 `torchrun` 内，不 fork）：
   - `shmem_ptr` 对端 GVA 与 `win.data_ptr()` 一致。
   - `torch.copy_` 到 `_construct_storage_from_data_pointer` 包出来的对端 view：**两边 golden 都过**。
   - 对端 wrap-read 也对。  
   结论：SHMEM 对端 GVA **在拥有 SHMEM 的进程里是合法 GM**。L3 `allocate_domain` 是在 **chip 子进程** 里做 ACL IPC import；我们的 `domain_provider` 把父进程 `buffer_ptrs` 直接塞进 `windowsIn`，子进程设备页表里没有这些映射。

5. **修复（只改 pypto）**：08 不再走 L3 `DistributedWorker.prepare()` fork。  
   - `ChipWorker`（L2，进程内）launch TSTORE/TPUT/TLOAD。  
   - `CommContext` 打进 SHMEM 窗首槽 `_comm_ctx`，不再用父进程 `torch.empty`。  
   - kernel ABI：tensors 在前，`MaterializeDistTensorCtx` 的 ctx 指针作 uint64 scalar。  
   - allreduce：host `pld.tensor.allreduce` 仍编译出 `builtin.tensor.allreduce__sum__fp16`；独立 launch 该 builtin 会 UB 越界。双卡求和改成同一套窗上的 `remote_load` + `pl.add`（TLOAD），live-input golden 过。

6. **两次 `torchrun --nproc_per_node=2` 均过**：TSTORE / TPUT / allreduce golden + `GLOO_SHMEM_COLLECTIVES_PASS`。日志：goal scratch `gloo_tput_run1.log` / `gloo_tput_run2.log`。

单元测试：`pytest tests/st/distributed/test_gloo_shmem_window.py` 8 passed。

## 已知风险

- NPUSHMEM 无 `barrier`/`put_signal`，跨卡可见性靠 ChipWorker 同步返回 + Gloo CPU barrier。
- L3 fork 子进程仍然看不到父进程 SHMEM GVA；跨进程 host orch 若要复用这套窗，需要子进程侧 mapping，或继续用进程内 ChipWorker。
- host mesh `pld.tensor.allreduce` builtin 在 2 进程独立 launch 时 UB 越界，尚未作为数据面。
